# HAKBa の準拠例・違反例

以下は Context の意味を示す判定例であり、作業の順序、修正方法、報告形式を規定しない。

| 観測できる状態 | 判定 | 根拠 |
| --- | --- | --- |
| Output の価格の根拠が、自身の `draft: true` Knowledge だけである | 違反 | H-06・H-08：未承認の情報は根拠にできない |
| 自身と祖先の承認済み Knowledge に根拠のない価格が Output に含まれていない | この主張について適合 | H-08・H-09：不足する根拠を未承認情報で補っていない |
| 作業 Space の兄弟にある承認済み Knowledge を根拠に Output の業務ルールが記載されている | 違反 | H-03・H-08：承認済みでも兄弟 Space は範囲外 |
| 自身の承認済み Knowledge から兄弟 Space へのリンクを辿り、その内容を Output に追加している | 違反 | H-03・H-09：リンクによる範囲拡張はない |
| Source の CSV にだけある数値が Output に引用されている | 違反 | H-08：Source の直接利用に相当する |
| Source にだけある数値が `_index.md` に転記され、それを根拠に Output に追加されている | 違反 | H-09：Context への転記は承認を代替しない |
| 同じ事項に関する祖先の承認済み一般方針より、自身の承認済み例外が適用されている | 適合 | H-04：近い Space の情報が優先される |
| `draft: "false"`、draft 欠落、重複キーのある Knowledge が未承認として扱われている | 適合 | H-06：真偽値 false の明示とは異なる |
| ユーザーが一部だけ承認したファイル全体が `draft: false` になっている | 違反 | H-05：ファイル全体の承認ではない |
| AI が表現改善した Knowledge が同じ変更で `draft: true` になり、他のメタデータは保持されている | 適合 | H-07：内容編集に伴う状態遷移 |
| 承認済み Knowledge を内容を変えず有効かつ有用な最も祖先側の Space へ移動し、draft 状態を維持している | 適合 | H-07・H-12：移動だけでは内容編集に当たらない |
| 上記の移動に伴い AI がリンクを書き換えた承認済み Knowledge が、再承認なしで false のままである | 違反 | H-07：リンク元は内容編集に該当する |
| 同一 Space に置き換え前後の相反する情報が、どちらも現在の Knowledge として残っている | 違反 | H-11：最新性を損なう共存 |
| 参照範囲外の古い Space に、その当時の Knowledge が残っている | 適合 | H-03・H-11：全 Space の最新化は要求しない |
| 同一 Space に取得日が異なる `261018_調査.csv` と `261020_調査.csv` が Source として併存する | 既定の保存規約に適合 | Source は重複を許容し、日付で鮮度を区別する。H-11 は Knowledge が対象 |
| 同内容を含む `261018_報告.pdf` と `261020_報告.pdf` が Output として併存する | 既定の保存規約に適合 | Output も重複を許容する。各 Output の根拠には H-08・H-09 が適用される |
| 設計作業で得たA社全体に有効かつ有用な新規 Knowledge が、祖父母のA社 Space にある | 適合 | H-12：作業場所によらず有用な最も祖先側へ配置する |
| ルートでも有効かつ有用な設計原則を、今必要なのが設計 Space だけという理由でそこに新規作成している | 違反 | H-12：現在の参照需要だけで配置を狭めない |
| A社固有の前提でのみ有効な知識を、A社 Space より上のルートに新規作成している | 違反 | H-12：有効かつ有用な範囲を越えて配置しない |
