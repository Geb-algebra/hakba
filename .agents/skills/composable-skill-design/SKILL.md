# Composable Skill Design

この Skill は Skill 作成のプロセスを規定せず、作成される Skill の設計に適用する知識と制約だけを提供する。
作業手順、成果物、完了条件、検証の手順や方法は、併用する Process Skill またはユーザーの指示に委ねる。

## 設計モデル

- **Process**: 目的を達成するために AI が行う一連の作業。
- **Context**: Process の判断や実行に利用される知識、規則、情報。
- **Process Skill**: 追加の Context を持たず、特定の Context に依存しない、素の Process を定義する Skill。
- **Context Skill**: Process を定義せず、特定の Process に依存しない、一貫した Context を提供する Skill。
- **目的**: 何のために Process を行うかの規定。
- **成果**: 目的を達成したことで観測できる結果。
- **不変条件**: Process の成果、または Context の規則が適用される対象で、必ず満たすべき状態。対象の実際の状態を観測し、適合または違反を照合できる条件として表す。

一つの Process Skill に、適用可能な複数の Context Skill を同時に組み合わせる。
Process Skill が活動全体を一貫して規定し、Context Skill がその活動で使う判断材料を追加する。

## 分類の境界

次の情報は Process に属する。

- 活動の目的
- 観測可能な成果または成果物
- 成果が満たす不変条件
- 完了条件
- 活動全体に対する制約
- 作業手順、順序、分岐
- 出力先、出力形式、報告方法

次の情報は Context に属する。

- ドメイン知識と用語
- 業務規則、設計規則、コーディング規約
- 判断基準、評価観点、組織固有の知見
- ツール固有の情報、コマンドの意味、利用上の前提や注意
- 規則の背景、適用範囲、不変条件、準拠例、違反例

個別の規則が行為を禁止または要求しても、それだけでは Process ではない。
例えば「注文を直接 cancelled に変更してはならない」は Context だが、
「最初に差分を確認し、次にテストし、最後に結果を書く」は活動全体の順序を定める Process である。

適用範囲の記述も、それだけでは Process ではない。
「実装・変更・レビュー時に適用する」は Context が利用可能な場面を示すだけで、各活動の目的や成果を定義しない。

## 不変条件

ここに列挙した条件はすべて必須である。推奨事項として緩めたり、例外を暗黙に補ったりしない。

### すべての Skill に共通する不変条件

- **C-01 単一分類**: 一つの Skill は Process Skill または Context Skill のどちらか一方でなければならない。
- **C-02 非混在**: 一つの Skill に Process と Context を混在させてはならない。両方が必要なら、独立した Skill に分離できる境界で扱わなければならない。
- **C-03 責務の一貫性**: Skill の全内容は、選んだ分類の単一で一貫した責務に属さなければならない。無関係な Process または Context を寄せ集めてはならない。
- **C-04 適用範囲の明確性**: description は、Skill が提供する内容と、それが適用される場面または対象を正確に示さなければならない。
- **C-05 境界の明確性**: 対象と対象外を誤認し得る Context では、その境界を description または本文から判定できなければならない。
- **C-06 合成可能性**: Skill は、一つの Process Skill と複数の適用可能な Context Skill を同時利用する構成を妨げてはならない。
- **C-07 非競合性**: Skill は、自分の分類が所有しない目的、成果、知識、規則を上書きしたり、それらの優先順位を独自に定めたりしてはならない。
- **C-08 依存の最小性**: Skill は、自身の責務に本質的でない特定のドメイン、プロジェクト、ツール、ファイル配置、Process、Context に依存してはならない。
- **C-09 記述の実質一致**: 名前、description、本文、例、同梱リソースは同じ分類と責務を表し、本文外に反対分類の指示を隠してはならない。
- **C-10 例による逸脱禁止**: 例、テンプレート、サンプルコードは規範本文と同じ不変条件を満たし、例を通じて Process と Context を再混在させてはならない。

### Process Skill の不変条件

- **P-01 目的の明示**: Process を何のために行うかが明示されていなければならない。
- **P-02 成果の明示**: 目的の達成を観測できる結果が明示され、その成果が満たす検証可能な不変条件を必ず含めなければならない。
- **P-03 不変条件の検証可能性**: 成果の各不変条件は、完了後の対象または成果物から実際の状態を観測し、その条件を満たすか否かを照合できる具体性を持たなければならない。自動検証できる必要はないが、観測事実だけでは判定できない曖昧な表現にしてはならない。
- **P-04 目的・成果・不変条件の整合**: 成果とその不変条件は目的の達成を観測できるものであり、目的はその成果を作る理由を説明できなければならない。
- **P-05 Context の排除**: Process から切り離せるドメイン知識、設計規則、コーディング規約、判断基準、組織固有の知見、ツール固有情報を含めてはならない。
- **P-06 特定 Context への非依存**: 特定の Context Skill、特定ドメインの知識、特定資料、特定プロジェクトの規則が存在することを前提にしてはならない。
- **P-07 複数 Context の受容**: 適用可能な Context Skill を複数同時に利用できなければならず、一つだけを選ばせたり、受け入れる Context を不必要に限定したりしてはならない。
- **P-08 補足の根拠**: 完了条件、制約、手順、出力形式などの補足は、その内容をユーザーが明示的に要求したか、実利用で同じ失敗が繰り返されたという具体的な根拠がある場合だけ含めなければならない。作者による脆弱性の予測、一般的なベストプラクティス、「役立ちそう」という判断だけでは追加してはならない。
- **P-09 目的・成果優先**: P-08 の根拠がない Process Skill は、目的、成果、および成果の不変条件だけで構成しなければならない。根拠がある場合も、その要求または反復失敗に直接対応する最小限の補足だけを含め、これらから AI が判断できる事項、一般的な作業能力で補える事項、まだ観測されていない失敗への予防策を固定してはならない。
- **P-10 本質的依存の抽象性**: Process の成立にある種類の Context が不可欠な場合、必要な情報の種類は規定できるが、固有のドメイン、資料名、保存場所、Context Skill 名に固定してはならない。
- **P-11 汎用性**: 目的と成果を変えずに異なるドメイン、プロジェクト、重要度、実装方式へ適用できる余地を、不必要に失ってはならない。

### Context Skill の不変条件

- **X-01 Context 限定**: AI が Process で利用する知識、規則、情報、判断基準だけを提供しなければならない。
- **X-02 Process の排除**: 活動全体の目的、成果、完了条件、作業手順、出力先、出力形式、報告方法を定義してはならない。
- **X-03 単独完結の禁止**: Context Skill 単独で活動を開始から完了まで遂行させる構成にしてはならない。
- **X-04 特定 Process への非依存**: 特定の Process Skill や、その固有の手順・成果物が存在することを前提にしてはならない。
- **X-05 複数 Process からの再利用性**: Context の意味が成立する範囲で、実装、変更、レビュー、説明など異なる Process から利用できなければならない。
- **X-06 適用範囲**: 知識や規則を適用する機能、処理、役割、環境などの範囲を判定できなければならない。誤適用の可能性がある場合は対象外も判定できなければならない。
- **X-07 判断可能性**: AI が未知の事例にも知識や規則を適用できるだけの意味、関係、条件を提供しなければならない。意図の理解が必要な規則には、その背景または理由を含めなければならない。
- **X-08 扱い方の委譲**: 何を知り、何を規則違反または望ましいと判断するかを提供し、その判断結果をどう処理・修正・報告するかは Process Skill に委ねなければならない。
- **X-09 活動順序の禁止**: Context の説明に必要な局所的な因果関係やツール操作を除き、活動全体の開始順序、工程、終了条件を定めてはならない。
- **X-10 出力契約の禁止**: ファイル名、テンプレート、表形式、回答文面など、活動全体の成果物契約を設けてはならない。
- **X-11 共存性**: 他の Context Skill と同時適用しても Process の所有権を奪わず、独自の作業手順や成果物を競合させてはならない。
- **X-12 Process 関連スコープの許容範囲**: Context が特定種類の活動でのみ意味を持つ場合、その活動を適用範囲として示すことはできるが、その活動自体の目的、成果、進め方を定義してはならない。
- **X-13 構成の適合性**: 本文の構成は Context の性質に合わせなければならず、背景、用語、関係、規則、適用範囲、不変条件、準拠例、違反例、コマンド、前提条件、注意事項のうち理解に必要なものだけを用いなければならない。
- **X-14 局所指示の限定**: Context 内の命令や禁止は、ドメイン規則またはツール利用上の規則として対象を限定し、Skill を利用するエージェントの活動全体を指揮してはならない。
- **X-15 条件付き不変条件**: 規約、ルール、ポリシー、設計原則など、対象の準拠状態を定める Context Skill は、その Context が要求する不変条件を含めなければならない。用語、事実、概念間の関係などの記述的なドメイン知識だけを提供し、準拠状態を定めない Context Skill には、不変条件を作ってはならない。
- **X-16 不変条件の網羅性と検証可能性**: X-15 に該当する場合、適用範囲内で必ず満たすべき条件をすべて列挙し、対象の実際の状態を観測して各条件への適合または違反を照合できる具体性を持たせなければならない。

## 境界事例

| 記述 | 分類 | 理由 |
|---|---|---|
| 「利用可能な知識を使い、コードから問題を発見する」 | Process | 活動の目的を定める。 |
| 「結果を `review.md` の表として保存する」 | Process | 成果物と出力形式を定める。 |
| 「レポートの各指摘に対象箇所と根拠がある」 | Process | 成果が必ず満たす検証可能な不変条件を定める。 |
| 「すべての SQL はパラメータ化する」 | Context | 実装・レビューなどで使う規則を与える。 |
| 「違反を見つけたら重大度順に報告する」 | Process | 判断後の処理と報告方法を定める。 |
| 「この規則は API、バッチ、管理画面に適用する」 | Context | 規則の適用範囲を定める。 |
| 「承認後にだけ注文状態を変更できる」 | Context | ドメイン上の条件と因果関係を与える。 |
| 「この CLI は認証後に `deploy` を実行する」 | Context | ツール固有の前提と操作知識を与える。 |
| 「まず CLI でデプロイし、次に動作確認し、最後に報告する」 | Process | 活動全体の工程を定める。 |

## 競合時の意味

ユーザーの依頼や併用 Skill が Process を定義している場合、この Skill の Context はその Process の設計判断に適用される。
この Skill 自体は作成順序、ファイル配置、成果物形式、検証手順を追加しない。
ただし、併用する指示が Process と Context の混在を最終 Skill に要求する場合、その最終 Skill は本設計の不変条件を満たさない。
